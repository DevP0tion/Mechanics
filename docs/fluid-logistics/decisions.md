# 결정 기록

## 1. 요소 목록

요소마다 필드 **이름 / 역할 / 연결 대상 / 비고**로 기록한다. 정하지 않은 필드는 **`미정`**.

요소 수: 3

| 이름 | 역할 | 연결 대상 | 비고 |
| --- | --- | --- | --- |
| 파이프 | 유체를 옮김 | **`미정`** | **`미정`** |
| 탱크 | 유체를 담아둠 | **`미정`** | 멀티블럭 — 조립형 가변 구조 (여러 블록을 배치해 하나의 탱크로 인식) |
| 펌프 | 유체를 끌어옴 | **`미정`** | **`미정`** |

## 2. 결정 목록

결정마다 한 줄, 질문 주기 번호를 붙인다. 바뀐 결정은 지우지 않고 '대체됨' 표시 후 새 줄을 추가한다.

- 1-1. 핵심 부품은 파이프, 탱크, 펌프.
- 1-2. 역할: 파이프 = 유체를 옮김, 탱크 = 유체를 담아둠, 펌프 = 유체를 끌어옴.
- 1-3. 탱크는 멀티블럭으로 구현하며, 조립형 가변 구조(여러 블록을 배치해 하나의 탱크로 인식)로 함.
- 1-4. 조립형 탱크의 구조 인식 규칙(이름·파라미터·동작)은 이번 세션에서 정의함 (세션 범위 확장).

## 3. 미결 목록

태그: `[미정]`, `[문제]`, `[규칙 빈틈]`, `[확인]`, `note`

- `[미정]` 파이프/탱크 물류 방식의 세부 조정 (기획서 열린 항목)
- `note` D2: 커스텀 오브젝트 레이어의 렌더링·저장 자동 처리 여부는 구현 단계에서 검증
- `[규칙 빈틈]` 조립형 가변 탱크(1-3): 엔진 기본 기능이 아님(D3 MultiTile은 고정 크기만 지원). 구조 인식 규칙의 정의(이름·파라미터·동작)가 필요함. — 이번 세션에서 정의 진행 중 (결정 1-4)
- `note` 조립형 탱크가 리전 경계를 넘으면 일부 리전만 언로드될 수 있음(D5) — 구현 단계에서 검토.
