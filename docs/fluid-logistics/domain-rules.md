# 도메인 규칙

출처는 Necesse 1.3.3 서버판 `Server.jar` 디컴파일로 확인한 사실이다.

## 엔진 제약 (Claude 조사)

- **D1.** 타일 하나에 오브젝트는 레이어당 1개. 기본 레이어 4개:
  - `base` — 일반 오브젝트·벽·가구
  - `tile` — 카펫·풀 같은 바닥 장식
  - `wallDecor`
  - `tableDecor`

  오브젝트마다 들어갈 수 있는 레이어가 정해져 있다.
- **D2.** 모드가 새 오브젝트 레이어를 등록할 수 있다(`ObjectLayerRegistry.registerLayer`). 클라이언트 전용 모드는 불가. 렌더링·저장 자동 처리 여부는 미검증 — 구현 단계에서 검증 필요.
- **D3.** 오브젝트는 4방향 회전과 다중 타일(`MultiTile`)을 지원한다.
- **D4.** 상태를 가진 오브젝트는 `ObjectEntity`로 구현한다. 서버 틱 초당 20회, 저장·불러오기와 클라이언트 동기화 패킷을 지원한다.
- **D5.** 플레이어 주변·정착지(settlement) 영역 밖 리전은 일정 시간 뒤 언로드된다(기본 약 30초, 설정값 `unloadLevelsCooldown`). 언로드된 곳의 오브젝트는 틱이 돌지 않는다. 정착지 영역은 로드가 유지된다.
- **D6.** 와이어는 타일마다 4색(빨강·초록·파랑·노랑). 오브젝트는 `onWireUpdate`로 신호를 받을 수 있다(압력판·트랩·가로등·TNT 등이 사용).
- **D7.** 액체는 타일이며 양(volume) 개념이 없다. 액체 타일 6종:
  - `watertile`
  - `lavatile`
  - `liquidslimetile`
  - `liquidoozetile`
  - `spiritwatertile`
  - `quicksandtile`

  물은 해안 거리 기반으로 깊이와 해수/담수가 계산된다(`LiquidManager`).
- **D8.** 버킷으로 액체 타일을 퍼면 그 자리가 흙이 되고 해당 액체의 타일 아이템을 받는다(다시 배치 가능). 깊은 바다(깊이 -3 미만)는 불가. 무한 물 버킷이 존재한다.
- **D9.** `ObjectEntity`에 전용 UI 창을 붙일 수 있다(`ContainerRegistry.registerOEContainer`). 마우스 오버 툴팁 가능.
- **D10.** 월드는 2D 탑다운 타일 격자임. 높이 방향으로 블럭을 쌓는 개념이 없으므로, 여러 블럭으로 이루어진 구조는 평면 배치로만 만들 수 있음.

## 세션 중 수집한 규칙

- **S1.** 바닐라 벽 티어(`toolTier`):
  - 0 = 나무 계열(wood, pine, palm, willow, dryad, bamboo), stone, sandstone, swampstone, snowstone, granite, ice, brick
  - 1 = dungeon
  - 2 = deepstone
  - 6 = obsidian, deepsnowstone
  - 7 = basalt
  - 8 = deepswampstone
  - 9 = deepsandstone
  - 10 = crypt, spidercastle, dawn, dusk, ancientruin, raven, arcanic, factory
- **S2.** 바닐라 벽 중 광석·주괴로 만드는 벽은 없음. 나무 외 벽의 재료는 돌류(stone, granite, deepstone 등), 점토(brick), 흑요석(obsidian), 고철(factory), 서리 조각·깃털·마나 등.
- **S3.** 물결 셰이더(`LiquidShader`): 레벨 그리기에서 타일 단계의 액체 목록(`LevelTileLiquidDrawOptions`)에만 적용됨. 모든 타일의 `addDrawables`가 이 목록을 받으므로, 모드 타일(예: 탱크용 바닥타일)도 액체 그림을 제출해 셰이더를 거칠 수 있음. 셰이더는 리전별 액체 데이터 텍스처(깊이·해수·해안·투명도, `LiquidManager.updateTextures`)를 읽기 때문에, 액체가 아닌 칸은 그대로면 육지 값으로 처리됨 → 해당 칸 값을 바꾸는 패치(`@ModMethodPatch`)가 필요할 수 있음. 오브젝트는 정렬 그리기 단계라 셰이더 밖에서 그려짐 — 물 텍스처의 애니메이션 프레임은 빌려 쓸 수 있으나 셰이더 효과는 없음. GLSL 원본은 서버판에 없어 미확인.
- **S4.** 액체 그리기는 3단계: (1) 액체 아래 단계(셰이더 없음) — 액체 밑 지면 타일(`getUnderLiquidTile`)을 일반 텍스처로 그림 (2) 액체 단계(물결 셰이더) — 물 텍스처 4종(담수/해수 × 얕음/깊음, 애니메이션 프레임)을 리전 액체 데이터로 섞어 그림 (3) 액체 위 단계(셰이더 없음) — 다리, 옛 방식에서는 물 위 장식(물 타일은 일부 칸에 둥둥 뜬 스프라이트). 이후 오브젝트가 정렬 그리기 단계에서 그 위에 그려짐. 모드 쪽 연결 지점: `LevelDrawUtils.addTileBasedDrawProcesses`(private, 타일 단계 수집)에 `@ModMethodPatch`로 액체 목록 추가, `LiquidManager.updateTextures`에 패치로 탱크 내부 칸 텍스처 값 지정. 오브젝트의 `addDrawables`는 액체 목록을 받지 않음.
- **S5.** 바닐라 곡괭이(`CustomPickaxeToolItem`: 채굴 위력 toolDps / 곡괭이 티어 toolTier): wood 50/0, copper 65/0, iron 80/0, gold 95/0, frost 110/1, demonic 125/2, runic 140/3, ivy 155/4, quartz 170/5, tungsten 185/6, glacial 200/7, dryad 215/8, mycelium 230/9, ancientfossil 245/10, ice 245/10. nightsteel·spiderite 곡괭이는 없음.
- **S6.** 광석의 toolTier는 광석이 박힌 암석의 티어를 따름(`RockOreObject`). 암석 티어: rock·snowrock 0, graniterock 2, swamprock 3, sandstonerock 4, deeprock 5, deepsnowrock 6, basaltrock 7, deepswamprock 8, deepsandstonerock 9, spiderrock 10, 크립트 nightsteel 바위 4. 그래서 copper·iron·gold는 0~9 여러 티어에 존재하고, demonic은 광석 없이 주괴만 있음.
- **S7.** nightsteel·spiderite 주괴 제작품(FALLEN_ANVIL): 무기(nightrazorboomerang, nightpiercer, phantompopper, phantomcaller / causticexecutioner, arachnidwebbow, webweaver, empresscommand), 갑옷(투구 4종·흉갑·부츠/각반), spideritearrow, spideritearmorstand. 채굴 도구 없음.
- **S8.** 오브젝트는 `canPlaceOnLiquid` 값을 켜면 액체 타일 위에 놓을 수 있음(`GameObject.canPlace`의 "liquid" 검사).
- **S9.** 바닐라에 통나무 아무거나(anylog)를 연료로 쓰는 오브젝트 엔티티가 있음(`AnyLogFueledInventoryObjectEntity`, `AnyLogFueledProcessingTechInventoryObjectEntity`).
- **S10.** 해수/담수는 타일 종류가 아니라 위치로 정해짐: 같은 `watertile`이라도 `LiquidManager.isSaltWater(x, y)`(해안 거리 기반 계산)로 구분됨.
- **S11.** 바닐라 작업대 계열(제작 기술 `RecipeTechRegistry`): 1 workstationduo(통나무 10, 손 제작 가능) → 2 demonicworkstationduo(demonicbar 5) → 3 tungstenworkstation(tungstenbar 8, quartz 4) → 4 fallenworkstation(upgradeshard 15, alchemyshard 15). 그 밖에 forge, carpentersbench, landscapingstation, ironanvil, alchemytable, 요리·가공(cookingpot 등), 데모닉·텅스텐·폴른 계열 모루·연금술대·목공대·조경대, transmutationstation이 있음. 모드는 자체 제작 기술(Tech)과 작업대를 등록할 수 있음(ExampleMod의 ExampleModTech·ExampleWorkstationObject).

## 멀티블럭 탱크 구조 규칙 (사용자 정의, 규칙 빈틈 해소)

- 이름: 멀티블럭 탱크 (3-1)
- 테두리: 광물 벽·탱크 컨트롤러·탱크 밸브로 된 직사각형 (5-13)
- 내부: ① 전부 유리 블럭 ② 완전히 빔 ③ 바닥 전부 탱크용 바닥타일, 그 위엔 유리 블럭만 (5-5, 5-11)
- 내부 판정(①②③)은 지하 파이프 레이어를 뺀 모든 레이어가 비어 있어야 함: 카펫 등 tile 레이어 오브젝트·벽 장식(wallDecor)·테이블 장식(tableDecor) 불가, 액체 바닥 타일 불가. ①은 base 레이어에 유리 블럭, 나머지 레이어는 빔. 지하 파이프는 탱크 내부 아래로 지나갈 수 있음(10-4) (N15-4)
- 크기: 내부 칸 기준 구조상 최소 ~ 5×5, 가로·세로 각각 (4-1, 7-1)
- 탱크 컨트롤러: 반드시 1개, 모서리 가능 (4-3, 4-5)
- 탱크 밸브: 개수 제한 없음·0개 가능, 모서리 불가 (4-4, 4-5)
- 인식: 블럭·바닥 타일 변경 시 자동 (5-1). 비활성 탱크에서 이미 놓여 있던 오브젝트의 제거와 내부 바닥 변경은 레벨 변경 패치(`TankChangePatches`)로 감지, 이 패치를 유지 (N16-2)
- 인식된 탱크의 내부에는 유리 블럭·탱크용 바닥타일·지하 파이프만 설치 가능. 그 밖은 모두 설치 거부: 모든 레이어의 오브젝트(바닐라 오브젝트, 카펫·벽 장식·테이블 장식, 다른 모드 블럭), 기본(base 레이어) 파이프, 액체 타일. 거부는 아이템 설명에 표시(N11-6). 비활성·무효 탱크는 대상 아님 (N15-5, N16-1)
- 용량: 내부 칸 수 기본 용량 × 광물 벽 최저 티어(채굴 위력) 배율, 값 **`미정`** (5-8, 8-1, 8-4)
- 벽 파괴 → 비활성화, 유체 보존, 데이터는 컨트롤러에 (5-9)
- 컨트롤러 파괴 → 유체 소실 (5-10)
- 상태 표시: 컨트롤러 UI 창 + 내부 마우스 오버 툴팁, 툴팁 형식 `유체 이름 현재값/최대값`(커서 오른쪽) (5-4, 6-2)
- 유체 표현: 모든 내부 조건에서 표시, 유리 블럭은 유리 블럭 텍스처·유체는 물결 셰이더 (6-3, 6-7)
- 두 탱크는 벽을 공유할 수 있고, 공유 벽에는 컨트롤러를 둘 수 없음(두 탱크로 동시 인식되면 설치 거부) (수치 세션 N8-1)
- 공유 벽 밸브는 설치 거부 (N11-1)
- 재조립으로 용량이 줄면 초과분 소실 (N11-2)
- 와이어 신호가 들어오면 밸브는 꺼짐 (N11-3)
- 설치 거부 규칙은 아이템 설명에 표시 (N11-6)
- 다른 블럭 설치로 나중에 생긴 충돌은 허용, 먼저 있던 쪽 우선: 공유 벽에 걸린 기존 밸브·컨트롤러는 원래 탱크 소속(새 탱크는 자기 것으로 세지 않음), 기존 펌프 옆에 밸브를 놓아도 펌프는 원래 공급원 유지 (N13-3)
- 밸브는 공유 불가: 새 탱크의 테두리에 다른 탱크 소속 밸브가 있으면 새 탱크는 인식 안 됨, 기존 탱크는 그대로, 설치 자체는 허용. 컨트롤러는 N13-3 그대로 (N15-3)
- 펌프–밸브 직접 연결은 렌치로 끊고 다시 이음. 펌프의 공급원은 붙은 곳이 아니라 연결된 곳 기준으로 판정. 이미 연결된 공급원이 있는 펌프에 렌치로 밸브를 더 연결할 때: 같은 유체이거나 빈 공급원이면 허용(같은 유체 공급원 여러 개 가능), 다른 유체면 기본적으로 거부(다중 유체 탱크는 TODO). 나중에 펌프 옆에 놓인 밸브는 펌프와 끊긴 상태로 시작해 펌프는 원래 공급원 유지 (N13-3, N16-3)
- 펌프 설치도 같은 유체 기준: 연결될 공급원이 모두 같은 유체이거나 비어 있으면 여러 개여도 설치 가능. 서로 다른 유체가 섞이게 되면 설치 거부, 거부는 펌프 아이템 설명에 표시(N11-6). N11-4의 설치 거부 규칙 대체 (N17-1)
- '합산'은 여러 펌프의 처리량이 더해지는 것: 같은 유체의 연결된 공급원이 여럿이어도 펌프 1개의 끌어오는 속도는 그대로. 여러 펌프가 같은 경로로 밀어내면 처리량이 더해지고, 그 펌프들이 파이프 상한(경로상 최저 운송량, N14-2)을 함께 나눠 씀. 연료 소모는 그대로. 세부 **`미정`**: 같은 유체 공급원이 여럿인 펌프 1개가 그 공급원들에서 끌어오는 순서 (N17-2, N18-1)
- 비어 있던 상태로 연결된 공급원이 나중에 다른 유체로 차도 연결은 유지. 펌프는 연결된 빈 파이프는 계속 채울 수 있지만, 다른 유체가 든 파이프로는 더 이상 내보내지 않음 (N17-3)
- 밸브 티어 = 제작에 쓴 광물 벽의 티어(아이템 데이터에 저장, 툴팁 표시, 설치 후 유지). 컨트롤러는 최고 티어로 취급. 배율은 테두리 광물 벽·밸브 중 최저 티어로 탱크 전체에 하나 (N13-5)
- 인식된 탱크가 걸친 리전은 함께 로드 유지 — 일부 리전만 언로드되어 비활성으로 남지 않음 (N15-6, 엔진 지원은 구현 단계에서 확인)

## 지하 파이프 레이어 규칙 (사용자 정의, 규칙 빈틈 해소)

- 파이프 전용 새 오브젝트 레이어 (9-1)
- 같은 칸의 기본 파이프와는 렌치로만 연결: 지하 파이프 위에 기본 파이프를 놓거나 그 반대로 놓으면 끊긴 상태로 시작 (9-5, N16-4)
- 같은 칸 기본↔지하 연결은 렌치 가운데 우클릭으로 끊거나 이음(12-8)
- 탱크 밸브와는 같은 칸일 때만 연결, 펌프와는 연결 안 됨 (9-9). 깊은 바다 위의 펌프도 같음: 지하 파이프와 직접 연결 안 되고, 액체 타일 위에 놓은 기본 파이프로 연결 (N17-4)
- 같은 칸의 지하 파이프–탱크 밸브 연결도 렌치 가운데 우클릭으로 끊거나 이음(13-5)
- 렌치 또는 지하 파이프 아이템을 들었을 때만 보임(9-6, 10-6)
- 별도 아이템으로 배치 (10-3)
- 렌치로만 철거, 곡괭이 불가(10-5, 12-8)
- 벽·오브젝트·액체 타일 아래 어디든 지나감 (10-4). 바다에서는 아래로 지나가기만 함 (N17-4)
- 탱크 내부 아래도 지나감: 탱크 내부 판정은 지하 파이프 레이어를 보지 않음 (N15-4)
- 상태(칸별 유체 양·끊김 플래그·도달 여부)는 레벨 단위 저장소에 보관(Necesse LevelData, 미검증), 리전 연동은 직접 구현 (N14-4)
- 동작 로직은 기본 파이프와 완전히 같음: N12·N13·N14 규칙 모두 적용 (N14-4)

## 유체 규칙 (사용자 정의, 규칙 빈틈 해소)

- 액체 7종: 물·용암·슬라임·우즈·영혼의 물·유사 (바닐라 액체 타일 6종, 12-1)·원유 (모드 전용, N17-5)
- 해수·담수는 다른 유체 (12-2)
- 원유: 바닐라 액체 타일이 없는 모드 전용 유체. 펌프가 깊은 해수(깊이 -3 미만, 11-9) 위에 있으면 원유만 나옴 — 담수·다른 액체는 그대로. 고급 화력 펌프 이상만 다룸(12-1, 12-6). 표시 이름·온도 **`미정`** (N17-5)
- 온도: 유체마다 고정, 값 **`미정`** (12-4)
- 기체: TODO (12-3)
- 펌프 티어별 제한: 수동=물, 화력=용암까지, 고급 화력부터 전부(원유 포함) (12-1, N17-5)
- 파이프 티어가 운송 가능한 종류·온도·상태를 정함 (9-2)
- 해수·담수 용어 (12-5)
- 펌프가 탱크에서 끌어올 때도 티어 제한 적용 (12-6)
- 탱크 하나·파이프 망 하나에 한 유체만 (12-7)
- 망 = 유체가 실제로 도달한 파이프의 집합, 빈 파이프는 어느 망에도 속하지 않음. 단일 유체·다른 유체 망 연결·티어 조건 모두 이 기준 (N13-1)
- 망은 망마다 따로 관리하고 경로 캐시와 그 무효화도 망 단위. 새로 놓은 펌프는 자기만의 새 망으로 시작하고, 그 유체가 같은 유체를 담은 다른 망에 도달하면 두 망이 합쳐져 하나로 관리됨 — 도달 기준 망(N13-1)과 일치 (N18-2)
- 망 재구성은 현행 유지: 변경이 생길 때마다 인접한 망을 다시 구성 (N18-3)
- 서로 다른 유체가 맞닿는 면은 자동으로 연결 안 됨(막힌 끝). 설치는 항상 허용, 설치 거부 아님 (N12-2, N13-2)
- 렌치로 끊은 상태(끊김 플래그)는 유지: 한쪽을 철거했다가 다시 놓아도 남은 쪽의 끊김은 그대로, 끊긴 면은 화면에 표시 (N16-4)
- 파이프를 비우는 동작은 없음: 유체를 바꾸려면 파이프를 철거하고, 그 안의 유체는 소실 (N12-1, N16-5)
- 기본 파이프는 액체 타일 위에 놓을 수 있음(`canPlaceOnLiquid`, S8). 지하 파이프는 바다 아래로 지나가기만 하고(10-4), 펌프–지하 파이프 직접 연결은 계속 없음(9-9) (N17-4)
- 파손 대상 = 유체가 새로 도달한 파이프, 연쇄 없음. 파손 사이클에는 그 파이프로 향하던 몫만 소실, 나머지 분배·연료 소모는 정상 (N14-1)
- 운송량 = 파이프 칸당 저장량이자 사이클당 상한: 경로상 최저 운송량이 그 경로가 펌프 1사이클에 옮기는 최대량, 값 **`미정`** (N14-2). 여러 펌프가 같은 경로로 밀어내면 처리량이 더해지고 이 상한을 함께 나눠 씀 (N18-1). 구현은 값이 정해질 때까지 임시 값(코드 TODO) (N15-2)
- 언로드된 리전은 밀어내기의 막힌 끝. 단, 경로 중 그 리전 안에 있는 파이프가 모두 가득 차 있으면('가득 참'은 경로 기준) 그 리전은 건너뛰고 다음 리전의 파이프부터 판정. 언로드 리전이 여러 개 연속되어도 각 리전이 경로 기준으로 가득 차 있으면 이어서 건너뜀. 다시 로드된 뒤 다른 유체가 맞닿는 면은 자동으로 연결 안 됨(N13-2)이라 단일 유체 유지. 언로드 리전의 펌프는 멈춤, 정착지 영역은 로드 유지(D5) (N14-3, N15-1)
- 화력·고급 화력 펌프 연료는 출력이 아니라 시간으로 소모: 통나무에 한 번 불이 붙으면 받거나 내보내는 것이 있든 없든 타이머(통나무 1개 = 5초, N6-2)가 끝날 때까지 탐. 다시 불을 붙이는 것은 기존 작동 조건(목적지가 없거나 모두 가득 차면 멈춤, N7-4)을 따름 (N18-4)
