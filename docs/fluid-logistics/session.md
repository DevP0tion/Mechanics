# 기획서 — Mechanics 유체 물류 설계 세션

## 역할

- 사용자가 설계한다.
- Claude는 진행자다. 질문하고, 기록하고, 규칙 위반 지점을 지적한다.
- 사용자가 정하지 않은 항목은 모두 **`미정`** 상태로 둔다.

## 범위

- 구성요소 목록까지만 다룬다.
- 세부 수치·동작 규칙은 이번 세션에서 다루지 않는다.
- 예외: 멀티블럭 탱크의 구조 인식 규칙은 이번 세션에서 정의함 (결정 1-4로 범위 확장).

## 고정 결정

| 번호 | 결정 |
| --- | --- |
| F1 | modID `devp0tion.mechanics`, 표시 이름 Mechanics, 작성자 DevP0tion |
| F2 | 깔끔한 최소 구성으로 시작 (공식 ExampleMod는 Gradle 설정만 가져옴) |
| F3 | 텍스처(픽셀 아트)는 Claude가 그림 |
| F4 | 문서·캔버스 작업은 모두 자식 에이전트에 위임 |

### 열린 항목

- 파이프/탱크 물류 방향만 정했고, 세부는 세션에서 조정한다.

## 도메인 규칙

- Claude가 엔진 제약을 조사해 정리한다 → [domain-rules.md](domain-rules.md)
- 세션 중에 추가로 수집한다.

## 질문 순서

- 핵심 부품 먼저 → 주변 요소로 확장
- 언제든 변경 가능

## 진행 방식 (세션 중 변경)

- 설명이 필요한 질문은 설명과 질문 위젯을 같은 턴에 둔다. 설명이 너무 길면 아티팩트에 설명을 넣고 링크한다. (사용자 결정, 7주기)
- 기록 갱신은 끝난 뒤 커밋하고, 같은 턴에서 다음 질문으로 넘어간다.
